# Primary Data Yesod

Primary data is permanent. Interpretations are temporary. Invest in the structural layer, not more interpretation pipelines.

## Definition

> "Primary data is permanent. Interpretations are temporary."
> -- **2026-04-10** | Data Yesod session

> "no no no think only about PRIMARY DATA -- 359,167 messages, 132 repos, 1,427 commits, 31,832 videos consumed, 5,524 markdown docs -- nothing else. explain to be only from primary raw data not interpretations"
> -- **2026-01** | poly-next session

Yesod (יסוד) = Hebrew for foundation. The principle: the foundation layer of any data system must be the raw, primary data. Everything built on top -- summaries, analytics, visualizations, interpretations -- is temporary and replaceable. The primary data is the only thing that's permanent.

## Genesis

### The Yesod Session: April 10, 2026

A ~4-hour session that started from 2030 skills surveys and ended at a foundational data principle. The insight crystallized when the author saw the pattern across all his systems:

- Brain MCP: 377K messages (primary) vs. summaries/embeddings (derived)
- Torah corpus: source texts (primary) vs. translations/commentaries (derived)
- WOTC: raw tax documents (primary) vs. calculated outputs (derived)

In every case, the primary data outlasts the interpretation layer. Embeddings get re-generated. Summaries get rewritten. Analytics evolve. But the raw messages, raw texts, raw documents -- those are permanent.

## Evolution

### The Principle Applied

| Domain | Primary Data | Temporary Interpretations |
|--------|-------------|--------------------------|
| Brain MCP | 377K raw messages | Embeddings, summaries, analytics |
| Torah Corpus | Source texts (Gemara, Rishonim) | Translations, modern commentaries |
| Client Work | Raw documents, transactions | Reports, dashboards |
| Personal | Conversations, code, commits | Portfolios, presentations |
| Wiki | Quoted words, attributed sources | Synthesis pages, connection maps |

### The Investment Principle

Don't build more interpretation pipelines. Invest in:
1. **Capture quality** -- make sure primary data is captured cleanly
2. **Structural layer** -- organize primary data for future re-interpretation
3. **Permanence** -- primary data survives every tool migration, every reprocessing

The wiki materialization (12/12 interpretation tools -> wiki pages) was this principle in action: raw data stays in Brain MCP, interpretations live in wiki (replaceable).
